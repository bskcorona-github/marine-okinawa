## 2. 決定事項

### 2.1 地域
- 初期は宜野湾だけなので、**地域の仕組みは作らない**（2026-09-30・10-01 決定）。「地域から探す」の画面・導線も、地域マスタ（`regions`）も持たない。
- 集合場所・港はプランごとの文面で持つ（今のまま）。
- 地域を増やすことになった時点で、地域マスタ・プランとの紐付け・TOP の入口・地域ページ（`/areas/[slug]`）をまとめて追加する。

### 2.2 アクティビティとプラン
- アクティビティマスタ（`activities`）を持ち、プランはアクティビティに紐付ける。TOP の主な入口は「アクティビティから探す」。
- アクティビティページ（`/activities/[slug]`）に、そのアクティビティのプランを一覧で出す（SEO の受け皿）。
- 初期 5 メニューを公開し、tagoo から移植した他のプランは非公開（下書き）にしてデータは残す。
  - パラセーリング・フライボード・マリンスポーツは移植済みの原稿を使う。
  - 体験ダイビング・ボートシュノーケリングは原稿がないため、原稿待ちの下書きを作る（要：顧客から原稿・写真）。
- プランの状態：公開／非公開／受付停止（ページは見られるが申込不可）。「在庫確認中」は受付停止の文言で表す。
- 1 プランに実施候補事業者を複数紐付ける（`menu_operators`）。予約ごとに組合が実施事業者を割り当てる。
  - 2026-10-01 更新：プランは原則として**事業者が登録し、その事業者が実施する**（2.11）。実施候補と割り当ては、組合が作るプランと、事業者の都合で別の事業者に頼むときに使う。

### 2.3 予約の流れと状態
申込時にお客様は空き枠（目安）から希望の回を選ぶ。枠は仮受付の時点で押さえ、取消・不可回答で戻す（目安の空き状況を正しく保つため）。

| 状態 | 意味 | 次へ進める人 |
|---|---|---|
| 仮受付（requested） | フォーム送信直後。まだ確定していない | 組合 |
| 内容確認中（reviewing） | 組合が入力内容を確認 | 組合 |
| 事業者確認中（operator_checking） | 候補事業者へ空き・受入可否を照会中 | 事業者が回答 → 組合 |
| 支払待ち（awaiting_payment） | 実施可・条件を案内済み。お客様の支払い待ち | お客様が支払い → 組合が入金確認 |
| 予約確定（confirmed） | 入金確認済み。お客様・事業者へ確定通知 | 事業者 |
| 催行済み（completed） | 事業者が催行を報告 | 組合 |
| 実績確認済み（verified） | 人数・内容・金額を組合が確定 | 組合（月次精算） |
| 精算済み（settled） | 月次精算まで完了 | — |
| 取消（cancelled）／天候中止（weather_cancelled）／無断キャンセル（no_show） | 例外。返金は支払い側で管理 | — |

- 「フォーム送信＝予約確定」にはしない。仮受付と予約確定は通知も分ける（受付完了メール／支払案内メール／予約確定メール）。
- 状態が変わるたびに、変更者・日時・前後の状態を履歴（`booking_status_events`）に残す。
- 組合は管理画面の手動予約（電話など）でも同じ台帳・同じ状態で管理する。

### 2.4 予約フォーム（お客様）
- 希望日時（空き枠から選択）、第 2 希望日時（任意・自由入力）、料金区分ごとの人数（大人・子供など）、申込者（氏名・電話・メール）、備考。
- 同意：参加条件・キャンセル規定・個人情報の取扱い（プライバシーポリシーへのリンク）。同意日時を保存する。
- 送信後の画面とメールでは「受付完了（まだ予約は確定していません）」を明示し、確定までの流れを案内する。
- 予約確定前は実施事業者名を出さない。確定後の画面・メールで実施事業者・集合場所・当日の連絡先を案内する。

### 2.5 支払い
- 組合が代理受領する前提で、決済は `PaymentProvider` の差し替えで対応する。初期の実装は「支払案内（振込先・決済 URL の案内文）＋管理画面での入金確認」。決済サービスが決まったら、決済リンク／Checkout を追加する。
  - 2026-10-01 決定：お客様の支払いは**カード（電子決済）だけ**。決済サービスは Stripe を使う（2.13）。お金を受け取るタイミングは今のまま（事業者が受入可と答え、組合が支払案内を送ったあと）。
- 表示価格の見出し（初期値「お支払総額」）、支払方法の案内文、手数料・管理費率、キャンセル料率、精算の締日・支払日、支払期限（日数）は設定値として管理画面から変える。

### 2.6 権限
- 組合・カネマサ管理者（`admin`）：全予約・全事業者・入金・精算・投稿・許認可を管理。
- 実施事業者（`operator`）：自社に割り当て・照会された案件だけ。お客様の情報は催行に必要な範囲だけを見せる。
  - 2026-10-01 追加：自社が掲載元のプランと、その空き枠だけを登録・編集できる（他社のプランは見られない）。
- 権限はすべてサーバー側で確認する（URL を直接開いても他社の案件は見られない）。管理者・事業者とも 2 要素認証を必須にする。

### 2.7 事業者
- 事業者登録フォーム（公開）：事業者情報・プラン情報・写真・保険・許認可・インボイス・精算口座。組合が審査して承認する。
- 資料のアップロード（PDF・画像、容量上限あり、実行ファイルは拒否）。有効期限を持つ資料は期限日を登録し、期限切れ・期限間近を管理画面に出す。郵送・持参の資料は管理者が受付登録する。
- 事業者専用画面（`/partner`）：受入可否の回答（可／不可／条件付き）、確定した自社予約の確認、催行報告（実施／中止／人数変更）、月次精算の確認、登録情報の更新申請。
  - 2026-10-01 追加：**自社のプランの登録・編集と、空き枠（開催時間・休み・定員）の管理**（2.11）。

### 2.8 精算
- 月締め後、実績確認済みの案件・キャンセル・返金を反映して事業者別の精算額を確定し、翌月末払いを基本にする。手数料率・締日・支払日は設定値。
- 予約台帳・精算は CSV 出力できるようにする。
- 2026-10-01 決定：精算の数字はすべて設定で変えられるようにし、初期値を入れておく（2.12）。

### 2.9 体験レポート・特典
- 催行済みの予約番号に紐付けて、評価・本文・写真を投稿できる。管理者の承認後に公開。
- 投稿者に次回特典（特典コード・有効期限・利用条件）を付与できる。

### 2.10 公開サイトの構成
- TOP：ファーストビューで「沖縄の海で体験を探して予約する」ことが分かる構成。主な入口は「アクティビティから探す」。補助導線は「おすすめ・新着」「初めての方へ」「予約方法」「安全への取組み」「お問い合わせ」。
- 協同組合が品質・安全・予約窓口を統括する印象にし、特定の事業者を前に出さない。
- プラン詳細の標準項目：プラン名・画像（複数）／お支払総額（見出しは設定値）／所要時間・開催時間／対象年齢・定員／集合場所（住所・地図・注意文）／持ち物（箇条書き）／料金に含まれるもの／参加条件・天候等による中止／キャンセル規定（共通＋個別）／予約申込ボタン。
- 固定ページ：初めての方へ／予約方法／安全への取組み／お問い合わせ（フォーム）／プライバシーポリシー／運営者情報。事前決済を始める前に特定商取引法に基づく表記を追加する。
- SEO：プラン・アクティビティ・体験記事のページを相互リンクする。title・description・OGP を管理画面から編集できる。構造化データを出力する。画像は最適化（WebP 等）。

### 2.11 事業者によるプランの登録（2026-10-01 決定）
- プランは**事業者が事業者画面で登録・編集する**。プランには掲載元の事業者（`menus.operator_id`）を持ち、その事業者が実施する。組合は管理画面で全プランを見て直せる（組合が作るプランも今までどおり持てる）。
- 公開サイトでは今までどおり事業者名を出さない（窓口は組合）。同じアクティビティに複数の事業者のプランが並ぶ。
- 公開までの流れ：事業者が下書きを作る → 「公開を申請」 → 組合が内容を確かめて公開（または理由をつけて差し戻し）。
- 公開したあとの変更
  - 空き枠（開催時間のルール・休み・定員・回ごとの休止）と受付の一時停止・再開は、**すぐ反映**する（当日の運用で必要なため）。
  - 文面・料金・写真などのプランの内容は、**変更の申請**として組合へ送り、組合が承認したら反映する（お客様に見せる内容と料金の誤りを防ぐ）。申請中は今の内容のまま公開し、申請は事業者が取り下げ・出し直しできる。
- 事業者が変えられないもの：URL（slug）、掲載元の事業者、公開・非公開の切り替え（組合の承認で行う）、おすすめ表示。
- 写真は事業者がアップロードする（PDF と同じく中身で形式を確かめる。JPEG・PNG・WebP、10MB まで）。保存先は資料と同じ `src/modules/storage/store.ts`（本番の保存先が決まったら差し替える）。
- 申込があったら、プランの事業者へ自動で受入確認を送る（設定で切り替え。初期値は「送る」）。組合は回答を見て支払案内を送る。

### 2.12 手数料・取消の設定値（2026-10-01 決定）
管理画面の設定で変えられるようにし、初期値は次のとおりにする（顧客が決めたら設定を変えるだけで済むように）。

| 設定 | 初期値 | 使うところ |
|---|---|---|
| 組合の手数料率 | 10% | 月次精算（事業者への支払額 ＝ 受け取った額 − 返金 − 手数料） |
| キャンセル料率（お客様の都合） | 7 日前まで 0%／前日まで 50%／当日・無断 100%（日数と率を変えられる） | 取消のときの返金予定額の初期値（予約ごとに直せる） |
| 天候中止の返金率 | 100%（全額返金） | 天候中止・一括の天候中止の返金予定額 |
| キャンセル料の配分 | 事業者の取り分にする（手数料率を引く） | 月次精算 |
| 締め日・支払日 | 月末締め・翌月末払い | 月次精算 |

### 2.13 カード決済・領収書（2026-10-01 決定）
- 決済は Stripe の Checkout（組合が 1 つの加盟店になる型）。支払案内のメールと予約確認ページに支払いのボタンを出し、決済が済んだら自動で入金を記録して予約確定にする（お客様・事業者へ確定のメール）。
- 返金は管理画面の「返金を記録」から Stripe へ返金を送る（記録と返金を一緒に行う）。
- 事業者への支払いは月次精算で組合から振り込む（Stripe Connect は使わない。事業者が増えたら検討する）。
- Stripe の鍵が設定されていないあいだは、今の「振込先の案内＋入金の記録」で動く。
- 領収書・インボイス：初期値は**組合が事業者の代理として受け取る型**（領収書は組合名で出し、「〇〇の代理として受領」と事業者名を載せる。精算明細に組合の手数料をインボイスの形で載せる）。組合を売り手にする型にも設定で切り替えられるようにする。どちらにするかは組合の税理士の確認後に決める。
- カード決済を始める前に、特定商取引法に基づく表記を公開する（2.10）。

## 4. 顧客に確認・用意してもらうもの
- 体験ダイビング・ボートシュノーケリング（ほか 3 メニューの最終原稿）の内容・料金・写真
- 組合の正式名称・所在地・連絡先・受付時間、ロゴ
- プライバシーポリシー・運営者情報の文面、キャンセル規定の共通文面
- 支払方法（当面の振込先や決済サービス）、支払期限の日数
- サイト名・ドメイン
- 要件書 14 章の未確定事項（税務方式、インボイス、手数料率、特典内容など）
- 2026-10-01 追加
  - 手数料率・キャンセル料率・天候中止の返金率の正式な値（初期値で作り、設定で変える）
  - 領収書・インボイスの型（代理受領か、組合が売り手か）を税理士に確認
  - Stripe のアカウント（組合名義）と、本番・テストの鍵
  - 写真・資料の本番の保存先（Vercel では今のディスク保存は使えない）
