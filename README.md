# 沖縄マリンアクティビティ総合ガイド・予約サイト

沖縄県マリンレジャー事業協同組合が運営する、マリンアクティビティの総合ガイド・予約サイト。お客様向けの公開サイト（アクティビティから探す・申込）、組合の管理画面（予約台帳・入金・取消・返金・タイムテーブル・事業者の管理）、実施事業者の事業者画面（受入確認の回答・催行報告）を 1 つの Next.js アプリで提供する。

- 設計（協同組合版）: `docs/superpowers/specs/2026-09-30-kumiai-portal-redesign.md`
- 顧客の要件書: `docs/requirements/`
- 実装計画: `docs/superpowers/plans/2026-10-01-kumiai-phase-a.md`（段階A）、`2026-10-01-kumiai-phase-b.md`（段階B）
- 以前の設計（即時予約・宜野湾港マリーナ版）: `docs/superpowers/specs/2026-09-28-marine-booking-design.md`（協同組合版と食い違う部分は協同組合版を優先）

## 予約の流れ

お客様の申込は「仮受付」で、まだ確定しない。組合が内容と空き状況を確認し、実施事業者に受入を確かめ、支払案内を送る。入金を確認した時点で「予約確定」になり、お客様に実施事業者と当日の連絡先を案内する。

仮受付 → 内容確認中 → 事業者確認中 → 支払待ち → 予約確定 → 催行済み → 実績確認済み → 精算済み（例外：取消・天候中止・無断キャンセル）

- 状態の遷移は `src/modules/booking/status.ts` の表だけで決まる。状態を変えるたびに `booking_status_events` に履歴が残る
- 枠（回の予約数）は仮受付の時点で押さえ、取消・天候中止で戻す
- 実施事業者の名前・電話は、予約確定まではお客様に出さない
- 料金の見出し（お支払総額）・支払方法の案内・支払期限の日数・共通のキャンセル規定・Web 申込の停止は、管理画面の「設定」で変える

## 事業者

- 組合が事業者ごとにログインアカウントを発行する（管理画面の「事業者」→ 各事業者 → アカウントを発行。仮パスワードは発行時に 1 回だけ表示）。ログイン画面は組合と共通（`/admin/login`）で、事業者は `/partner` に入る。どちらも 2 要素認証が必須
- プランは事業者が事業者画面（`/partner/plans`）で登録する。内容・料金・写真と、開催時間・空き枠（ルール・休み・定員）を自社のプランだけ登録・編集できる
  - 下書きは自由に直せる。「公開を申請」→ 組合がプランの編集画面の「公開の申請」で承認すると公開、理由をつけて差し戻せる
  - 公開後の内容・料金・写真の変更は「変更の申請」になり、組合が差分を見て承認すると反映する（承認まで今の内容で公開）。開催時間・休み・定員と受付の一時停止はすぐ反映する
  - 写真は JPEG・PNG・WebP（10MB まで）。資料と同じ保存先に置き、`/media/plan-images/[id]` で配信する
  - 審査待ちは管理画面のダッシュボードとプラン一覧（「審査待ち」）に出る。申請と結果はメールでも知らせる
- Web の申込があると、プランの事業者へ自動で受入確認を送る（設定の「申込を受けたら、プランの事業者へ自動で受入確認を送る」。外すと組合が手で依頼する）
- 組合はプランの実施候補から事業者を選んで受入確認を依頼することもできる（予約詳細の「事業者への受入確認」）。事業者は事業者画面で「受入可／条件付きで可／受入不可」を回答し、「受入可」ならその事業者が実施事業者になる
- 事業者に見せるのは、照会の段階では日時・プラン・人数・年齢・連絡事項だけ。予約確定後に代表者の氏名と電話を加える（メールアドレスは見せない）。他社の予約・照会は URL を直接開いても 404
- 催行報告：「実施」は実績人数つきで催行済みにする。「中止」「無断キャンセル」は報告として残し、組合が返金の扱いを決めて状態を変える
- 登録情報の変更は、事業者画面から申請し、組合が確認して反映する
- 事業者の登録申請は公開フォーム（`/ja/partner/apply`）から受け付け、組合が承認すると事業者になる
- 資料（保険・許認可・インボイスなど）：PDF・JPEG・PNG・WebP、1 ファイル 10MB まで（中身の先頭のバイトで形式を確かめる）。期限切れ・30 日以内はダッシュボードに出す。保存先は `STORAGE_DIR`（既定 `.storage/`）。本番の保存先（S3 互換など）が決まったら `src/modules/storage/store.ts` を差し替える

## 構成

| 役割           | 技術                                                          |
| -------------- | ------------------------------------------------------------- |
| フレームワーク | Next.js 16（App Router）/ TypeScript                          |
| DB             | Neon（PostgreSQL）/ Drizzle ORM                               |
| 認証           | Better Auth（組合・事業者：メール + パスワード + 2 要素認証） |
| メール         | Resend + React Email                                          |
| 多言語         | next-intl（日本語のみ。メッセージのキーは型で確かめる）       |
| テスト         | Vitest（単体・結合）/ Playwright（E2E）                       |

- お客様向け: `/ja`（TOP：アクティビティから探す）→ `/ja/activities/[slug]` → `/ja/menus/[slug]`（プラン詳細・空き状況）→ 申込 → `/ja/bookings/[token]`（申込・予約の確認）。ほかに `/ja/search`、固定ページ（`/ja/guide` など）、`/ja/contact`
- 管理画面: `/admin`（ダッシュボード）、予約台帳（検索・CSV）、タイムテーブル、手動予約、お問い合わせ、日報・集計（CSV）、プラン、アクティビティ、事業者（アカウント・資料・更新申請・登録申請）、固定ページ、設定
- 事業者画面: `/partner`（ホーム）、受入確認、予約・催行報告、登録情報（更新の申請）、資料
- ドメインロジック: `src/modules/<module>/`（DB を引数で受け取る関数。テストは同じ場所の `*.test.ts` / `*.int.test.ts`）

## セットアップ

前提: Node.js 22、Docker（テスト用 PostgreSQL）

```bash
npm install
cp .env.example .env.local        # 値を設定（MARINE_DATABASE_URL は Neon の pooled 接続文字列）
npm run db:up                     # テスト用 PostgreSQL（localhost:5433）
npm run db:migrate                # MARINE_DATABASE_URL の DB にマイグレーションを適用
npm run seed                      # ショップと最初の管理者（SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD）
npm run import:ginowan            # 初期データ（組合・アクティビティ・初期 5 メニュー）
npm run dev
```

`/admin/login` からログインすると、初回は 2 要素認証（認証アプリ）の設定を求められる。

テスト用の `.env.test`:

```dotenv
TEST_DATABASE_URL=postgres://postgres:postgres@localhost:5433/marine_test
E2E_DATABASE_URL=postgres://postgres:postgres@localhost:5433/marine_e2e
```

（`marine_test` / `marine_e2e` の DB は事前に作成しておく）

## 初期データ（`npm run import:ginowan`）

`docs/content/ginowan-marina.json`（tagoo.jp の宜野湾港マリーナのページから抽出）から、組合のサイトとして最初に公開するデータを作る（何度実行しても同じ結果）。

- アクティビティ 5 件：パラセーリング・フライボード・体験ダイビング・マリンスポーツ・ボートシュノーケリング
- 公開：パラセーリング（高さ 100m・150m・200m の 3 プランを 1 プランにまとめ、高さを料金区分にした）、フライボード
- 下書き（原稿・料金待ち）：体験ダイビング・マリンスポーツ2種セット・ボートシュノーケリング
- それ以外に移植していたプラン（釣り・貸切・ホエールウォッチングなど）はアーカイブ（データと過去の予約は残る）

取り込み後に管理画面で確認すること:

- **固定ページ**：初めての方へ・予約方法・安全への取組み・プライバシーポリシー・運営者情報は下書きの文面。組合の正式な文面に差し替える
- **設定**：組合の電話番号・メールアドレス・受付時間、支払方法の案内（振込先など）、共通のキャンセル規定
- **事業者 → ココマリン → オン期の期間**：元ページの表記（2026 年 4 月〜2027 年 1 月）しか入っていない。翌年のオン期を追加する
- **画像**：未登録。組合が用意した写真をプランの編集画面で登録する

## デプロイ（Vercel）

- 環境変数: `.env.example` の項目（`MAIL_DRIVER=resend`、`RESEND_API_KEY`、`CRON_SECRET` を設定）
- `vercel.json` の Cron が毎日 3:00（JST）に `/api/cron/sync-slots` を呼び、今日から 180 日分の回を作る
- マイグレーションはデプロイ前に `npm run db:migrate` で適用する
- `APP_URL`（本番 URL）は必須。未設定だとメールのリンクが作れない
- Web 申込は同じ IP から 10 分間に 5 件まで、お問い合わせは 10 分間に 3 件まで、事業者の登録申請は 1 時間に 3 件まで（`x-forwarded-for` を使う）
- 事業者の資料のアップロードのため、Server Action の本文の上限を 11MB にしている（`next.config.ts`）。資料の保存先はサーバーのディスク（`STORAGE_DIR`）なので、Vercel では永続化されない。本番の前に保存先を決めて差し替える
